# MostBox 开发与发行路线

更新日期：2026-11-22。本文管理客户端与发行范围。最高目标是**成为能脱离创始人长期存在的公共协议**；长期原则与协议任务统一见[长期方案与推进计划](decentralization-plan.md)。

首批用户已明确为愿意搭建远程节点、供朋友或公众使用的人。首批使用路径围绕搭建节点、让朋友或公众连接、加入群聊天和按需传文件，以及由群体持续维护可用性展开。产品体验目标是像微信一样方便地聊天和传文件；完全去中心化仍按公共协议独立性标准验收，不因支持自建节点就认定已经达成。节点公开提供使用不等于公开所有群的加入值。

## 已确定的顺序

先补齐公开规范与独立实现、可替代基础设施、聊天和文件可靠性、维护交接的证据。当前战略里程碑是：第三方依据公开材料实现最小兼容节点，在没有创始人服务和现场指导的情况下，与参考节点完成签名文本同步和文件接力。尚未通过此项验收。

客户端先开发、验证全功能版，再按实际应用商店及发行地区要求适配海外与中国大陆商店版。商店覆盖和商业规模不作为协议存续的前提；正式发行前仍需完成对应审核和合规工作。

三个版本共享同一代码库和协议核心，按发行目标生成不同安装包，不维护三套复制的业务代码。各版本的功能、权限、法律页面、签名、更新渠道和验收证据分别管理。

## 三个发行版本

| 版本                | 用途                              | 范围与状态                                                                                                                                                                        |
| ------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全功能版            | 官网、GitHub、自托管及开发测试    | 当前主线。完整频道聊天、文件传输与做种、本机和远程节点、身份、语音（实时通话仅 Web 与桌面端）和 MCP 按平台能力开发与验收；Web3 工具箱将移出主仓库；列入目标不代表全部功能已经完成 |
| 海外 APP 商店版     | App Store、Google Play 等海外商店 | 全功能版稳定后，按目标商店与国家或地区确定功能、内容管理、权限和隐私披露；不是全功能包改名后直接提交                                                                              |
| 中国大陆 APP 商店版 | 中国大陆应用商店                  | Android 包名已确定为 `most.people`；显示名、首发功能和发行渠道在适配阶段确定，备案内容必须与最终包一致                                                                            |

全功能版也需要满足实际分发地区的法律要求。海外商店版保留聊天时，按目标平台评估举报、屏蔽与内容处置能力；大陆版不沿用历史“知识库、无聊天”的材料，也不提前承诺仅靠关闭聊天即可完成合规。

## 当前代码与目标的差异

当前代码版本由根目录和 `app/` 的配置维护，不在路线文档中维护易过期的版本副本。

- `app/product-profiles.json` 目前只有 `most` 和 `inkbox` 两个 profile，尚未实现三个独立发行配置。
- `most` 是当前全功能配置，移动端 Android package 和 iOS Bundle ID 均为 `most.box`。
- `inkbox` 是“墨盒”裁剪配置，Android 包名与 iOS Bundle ID 均已改为 `most.people`。尚无正式签名密钥和候选包。
- `build:store`、`build:play` 和 EAS production 只代表现有构建格式或签名入口，不代表已经做过海外或大陆商店适配。
- 共享协议当前实现为 v2。早期不承担历史版本兼容，允许按[协议演进规则](protocol/v2/envelope.md#7-协议演进规则)进行不兼容升级，不默认增加兼容分支或旧数据迁移；文件名不作为内容身份。
- 群模型已明确为仅普通用户、唯一产品 `channelId` 和历史平权，文字默认同步保存、附件点击时下载，校验后默认继续做种；消息只显示哪些用户收到，不做已读，回执机制仍需设计。完整决定与实现差异统一见[群聊模型](chat-model.md)，旧版迁移记录不构成未来兼容要求。

## 当前开发重点

协议文档与 v2 升级已有基础。按[长期方案](decentralization-plan.md)推进独立实现、协议迭代与版本管理、基础设施接替、可靠性验收与维护分发交接。具体工作与状态只在长期方案和验证状态中维护。收到回执为低优先级，暂不开发，不作为当前 MVP 的验收门槛。本地屏蔽的新增或完善工作优先级很低，暂不安排，保留已有能力；只影响自己的显示，不扩展为群管理权限。“对节点运营者隐藏正文”的提案已撤回，不列入当前目标。

1. 围绕频道、签名文本与文件接力完善参考客户端的错误恢复与节点状态；界面、语音和工具入口按平台能力选择，不扩大最小独立实现的必选范围。移动端原生实时通话不再列入目标。
2. 提升连接与传输可靠性：复现蜂窝发现慢或超时，区分直连、已配置中继和真正经过中继的连接；覆盖重启恢复、大文件、空间不足和权限撤销。
3. 按系统验证生命周期：Android 后台保持已有实现，继续覆盖当前运行库、无充电、系统清理与超时；iOS 先完成当前版本的签名真机前台闭环，再记录挂起恢复边界。
4. 让第三方重放部署、恢复、构建与分发流程，并由实际群体自主维护节点。全功能版通过后冻结候选包，记录提交、签名、哈希、设备和网络；再确定两个商店版的功能矩阵与实施批次。

用户数据自管与自由更换节点为核心要求：先明确用户设备上的身份、群入口、已同步文字与已下载文件的保存、导出和恢复方案，再验证原节点永久下线且不配合时，用户能凭自行保管的材料换节点继续使用。具体边界见[群聊模型](chat-model.md#数据自管与节点更换)，不把现有账号备份视为完整恢复已通过。

群体自行维持可用性，建议愿意维护的群成员自建常在线服务器节点，加入群并保存、同步文字消息，帮助错峰上线的成员补齐；部署、重启和补齐流程仍需验收。服务器节点仍为普通成员，附件按需下载，没有可达副本时等待持有者上线。中继帮助在线端点连通，不自动提供离线消息或永久文件保存；额外的离线托管服务、中继服务和官方托管能力仍需独立设计与验证，不当作已完成能力。

## 商店适配阶段再做

- 为三个发行目标明确构建配置和升级渠道，评估是否采用独立包标识及数据目录；避免安装包误覆盖或更新到其他版本。
- 从 UI、路由、深链、HTTP/WebSocket、Bare 核心和原生权限验证功能边界，不能只隐藏按钮。
- 用最终分发包重新检查 SDK、网络行为、权限、图标、截图、用户手册和隐私披露。
- 按实际渠道分别处理正式签名、商店账号、版权材料、地区要求及中国大陆 APP 备案。
- 现有腾讯云草稿与公司资料由官网仓库的 [资质与备案状态](../../most.red/docs/release-readiness.md)维护；当前不提交旧 MostBox 草稿或旧版签名信息。
