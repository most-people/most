# MostBox 开发与发行路线

更新日期：2026-10-17。本文记录负责人确认的目标，是产品范围和开发顺序的统一入口。

## 已确定的顺序

先开发、验证全功能版，再根据实际应用商店及发行地区的要求适配海外商店版和中国大陆商店版。商店资料、备案与功能裁剪不作为当前全功能开发的前置任务；正式发行前仍需完成对应审核和合规工作。

三个版本共享同一代码库和协议核心，按发行目标生成不同安装包，不维护三套复制的业务代码。各版本的功能、权限、法律页面、签名、更新渠道和验收证据分别管理。

## 三个发行版本

| 版本                | 用途                              | 范围与状态                                                                                                                           |
| ------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 全功能版            | 官网、GitHub、自托管及开发测试    | 当前主线。完整频道聊天、文件传输与做种、本机和远程节点、身份、语音、Web3 和 MCP 按平台能力开发与验收；列入目标不代表全部功能已经完成 |
| 海外 APP 商店版     | App Store、Google Play 等海外商店 | 全功能版稳定后，按目标商店与国家或地区确定功能、内容管理、权限和隐私披露；不是全功能包改名后直接提交                                 |
| 中国大陆 APP 商店版 | 中国大陆应用商店                  | Android 包名已确定为 `most.red`；显示名、iOS Bundle ID、首发功能和发行渠道在适配阶段确定，备案内容必须与最终包一致                   |

全功能版也需要满足实际分发地区的法律要求。海外商店版保留聊天时，按目标平台评估举报、屏蔽与内容处置能力；大陆版不沿用历史“知识库、无聊天”的材料，也不提前承诺仅靠关闭聊天即可完成合规。

## 当前代码与目标的差异

当前代码版本由根目录和 `app/` 的配置维护；本次文档整理时均为 `0.5.3`。

- `app/product-profiles.json` 目前只有 `most` 和 `inkbox` 两个 profile，尚未实现三个独立发行配置。
- `most` 是当前全功能配置，移动端 Android package 和 iOS Bundle ID 均为 `most.box`。
- `inkbox` 是历史“墨盒”配置，包标识仍为 `red.most.mohe`，不能作为新的大陆版 `most.red` 候选包。保留现有代码供后续适配，不在文档清理时修改构建或签名身份。
- `build:store`、`build:play` 和 EAS production 只代表现有构建格式或签名入口，不代表已经做过海外或大陆商店适配。
- `most://`、UnixFS CID v1、topic 和 Hyperdrive `/<cid>` 等共享协议继续保持兼容；文件名不作为内容身份。

## 当前开发重点

1. 完成全功能闭环：频道与身份、文本和文件附件、照片与语音消息、本机与远程节点、工具入口及错误恢复。移动端实时通话尚未完成，必须以双真机音频收发验收。
2. 提升连接与传输可靠性：复现蜂窝发现慢或超时，区分直连、已配置中继和真正经过中继的连接；覆盖重启恢复、大文件、空间不足和权限撤销。
3. 按系统验证生命周期：Android 后台保持已有实现，继续覆盖当前运行库、无充电、系统清理与超时；iOS 先完成当前版本的签名真机前台闭环，再记录挂起恢复边界。
4. 全功能版通过后冻结候选包，记录提交、签名、哈希、设备和网络；再确定两个商店版的功能矩阵与实施批次。

中继帮助在线端点连通，不自动提供离线消息或永久文件保存。离线投递、额外中继服务和官方托管能力需要独立设计与验证，不当作已完成能力。

## 商店适配阶段再做

- 为三个发行目标明确构建配置和升级渠道，评估是否采用独立包标识及数据目录；避免安装包误覆盖或更新到其他版本。
- 从 UI、路由、深链、HTTP/WebSocket、Bare 核心和原生权限验证功能边界，不能只隐藏按钮。
- 用最终分发包重新检查 SDK、网络行为、权限、图标、截图、用户手册和隐私披露。
- 按实际渠道分别处理正式签名、商店账号、版权材料、地区要求及中国大陆 APP 备案。
- 现有腾讯云草稿与公司资料由官网仓库的 [资质与备案状态](../../most.red/docs/release-readiness.md)维护；当前不提交旧 MostBox 草稿或旧版签名信息。
