# CID drive：独立签名的设计理由

现行线上规则统一在 [文件发现与访问证明](protocol/v2/file-privacy.md) 和 [文件传输](protocol/v2/file-transfer.md)。本篇只保留独立签名设计的原因与证据入口，不另定义通道、派生公式或迁移规则。

## 为什么每个种子有自己的 drive

Hypercore 签名证明持钥写入者写了某块，其一致性前提是单写者。早期共享 drive 私钥使所有种子都能写入：坏节点可制造两条各自签名合法的分叉，Hypercore 无法按内容 CID 裁决，本机收到的冲突也不能靠换诚实来源消除。

内容是否正确由下载者重算 CID 决定。因此每个种子只签名自己的完整副本，通过一问一答提供自己 drive 的 key；坏来源的块留在独立 core 中，不污染诚实种子的 core。下载者依次尝试来源，校验通过才写入自己的 drive 并成为新种子。

## 证据与边界

独立签名实现于 2026-11-16，桌面 `4588061`、`24faed3`，移动 `22e8b04`。当时记录包含坏 peer 与诚实种子同时连接 50 次成功，以及此前 6 次中 1 次冲突失败；详见 [验证状态](validation-status.md)的“2026-11-15 坏对端探测（F2）”和“2026-11-16 CID drive 协议 v2”。这些历史结果不自动证明当前版本通过全部真机和真实网络门槛。

当前使用 `most-cid-drive/3`，带已知 CID 的连接绑定证明；0.5.x 到 0.8.0 的一次性迁移集中在 [现行规范](protocol/v2/file-privacy.md#8-迁移)。不把历史设计中的旧通道和旧命名公式保留为实现入口。

当前仍是完整下载后校验，不做多源并行、持久信誉、分片或纠删码。F1–F5 和发布者退出后的接力按 [验收指南](acceptance.md)验证。
