# MostBox `/hi` Landing Page 草稿

> 状态：内容方向已确认，作为 `/hi` 页面实现依据。

## 核心定位

**MostBox：每个人的知识大脑，AI-native 组织的协作基础。**

知识库是个人的大脑，文件系统是大脑的内容底座，AI 是使用大脑的能力，P2P 是人与人之间连接大脑的方式。

目标受众是普通人。每个人先整理和积累自己的知识库，再选择需要的知识、上下文与文件参与组织协作。

## 页面草稿

### 01｜首屏

# 每个人的知识大脑，AI-native 组织的协作基础

把笔记、文件、对话和经验整理成真正属于自己的知识库。

让 AI 在你的授权下理解和使用这些知识，再把需要的部分与其他人连接起来。

主按钮：**打开知识库**

次按钮：**下载 MostBox**

首屏展示真实知识库结构：知识目录、Markdown 内容、关联资料和 AI 操作状态。文件和节点能力作为知识库的底层支撑出现。

### 02｜概念

# 先让每个人拥有自己的大脑

每个人都在不断产生知识：读过的资料、做过的项目、解决问题的方法、聊天中形成的结论，以及只有自己理解的经验。

但这些内容通常散落在文件夹、聊天记录、收藏夹和不同软件里。它们被保存了，却没有真正成为可以持续使用的知识。

MostBox 从个人知识库开始。你按照自己的方式记录、连接和整理知识。它不是别人规定结构的企业文档系统，也不是把所有资料上传到同一个中心数据库。

这是属于你的长期大脑。

### 03｜问题

# AI 很强，但它每次都要重新认识你

新的 AI 对话通常从空白开始。你需要反复解释自己是谁、正在做什么、项目有哪些背景、哪些结论已经确认，以及相关文件放在哪里。

在组织中，这个问题会被进一步放大：

- 每个人掌握一部分信息，却没有形成自己的知识系统。
- 文档被上传到共享空间，却很快失去上下文。
- 聊天产生大量结论，却没有沉淀回知识库。
- 文件不断复制和重命名，很难确认内容和版本。
- AI 能生成结果，却无法继承组织成员长期积累的经验。

组织拥有很多资料，却没有形成真正可工作的集体知识。

### 04｜核心产品

# 知识库不是资料仓库，而是生产力容器

MostBox 知识库用普通 Markdown 保存内容。

你可以建立目录、搜索笔记、使用 Wiki 链接连接想法，并把聊天中的重要内容沉淀为长期笔记。

Git 记录知识如何发生变化，让你查看差异、提交版本、浏览历史，并恢复过去的内容。

图片、数据、视频和其他附件不需要复制进笔记。知识库使用 `most://` 引用文件，由 CID 确认它指向的究竟是哪一份内容。

知识库因此同时容纳：

- 你知道什么。
- 这些知识之间有什么关系。
- 知识如何演变。
- 结论依据哪些原始文件。
- AI 和其他人可以使用哪些部分。

### 05｜AI

# 让 AI 从你的知识出发，而不是每次从零开始

未来，AI 可以在明确授权下进入你的知识库。

它可以帮助你整理零散记录、发现已有知识之间的关系、寻找相关资料、总结项目背景，并把新的工作结果写回知识库。

重点不是让 AI 接管你的大脑，而是让它使用你已经建立的上下文。

你决定它可以访问哪些知识、执行哪些操作、哪些内容只能读取、哪些结果可以写回，以及什么时候撤销权限。

普通人不需要理解 MCP、API 或模型上下文。MostBox 应该把这些技术隐藏在自然的授权交互背后。

### 06｜组织

# 组织不是一个共享大脑，而是一群能够协作的个人大脑

传统组织知识库要求所有人维护同一个中心空间。时间久了，它往往变成少数人整理、多数人搜索不到、最终无人维护的文档仓库。

MostBox 选择另一条路径：每个人先建立和维护自己的知识库。知识仍然保留个人的理解方式、工作历史和上下文。

协作发生时，人们只分享当前需要的知识、笔记或文件，而不是交出自己的整个知识库。

AI 帮助不同人的知识建立连接：

```text
我的知识库
    ↓ 选择与授权
项目上下文 / 笔记 / CID 文件
    ↓
你的知识库
    ↓
继续理解、整理和生产
```

组织的知识不是被集中收走，而是在成员之间持续流动、引用和生长。

### 07｜P2P 与文件

# 每段知识，都能连接到可信的原始内容

文字只是知识的一部分。设计稿、数据集、视频、研究资料和项目产物同样构成一个人的知识背景。

MostBox 使用 CID 为文件建立稳定身份，通过 `most://` 在在线节点之间传播。

文件被移动或重命名，不会改变它的内容身份。接收方下载后重新计算 CID，确认拿到的是同一份内容。

下载成功的节点默认继续提供完整副本。只要还有持有者在线，知识库中的文件引用就可以继续传播。

P2P 不是页面的主角，而是让知识脱离单一平台、仍然能够被引用和协作的基础。

### 08｜使用场景

# 从个人整理开始，自然走向协作

- **个人知识管理**：记录读书、学习、项目和生活经验，把零散内容整理成能够长期积累的知识库。
- **AI 助手**：AI 使用个人知识库理解背景、查找资料和延续任务，不必每次重新解释自己。
- **项目协作**：成员分别整理自己的工作过程，再把与项目有关的笔记、结论和文件分享给其他人。
- **团队决策**：会议与聊天中的结论进入知识库，与依据、附件和后续变化保持关联。
- **新人加入**：新人获取经过整理的项目上下文，而不是面对庞大的共享文件夹和漫长的聊天历史。
- **Agent 协作**：一个 Agent 根据知识库完成工作，把结果写回或发布；另一个 Agent 继续使用经过确认的上下文和文件。

### 09｜今天与未来

# 今天整理自己的知识，未来连接彼此的大脑

今天已经具备：

- 本地 Markdown 知识库。
- 文件夹、搜索与 Wiki 链接。
- Git 差异、提交、历史与恢复。
- 聊天内容沉淀为笔记。
- 知识库备份与恢复。
- `most://` CID 附件引用。
- P2P 下载、校验与接力做种。
- 面向文件节点的受控 MCP 能力。

正在探索：

- AI 对知识库的受控读取与整理。
- AI 结果写回知识库。
- 可选择的知识上下文分享。
- 个人知识库之间的引用与协作。
- 由多个个人大脑组成的组织知识网络。

页面必须明确区分当前能力和未来方向，不能把未来能力描述成已经上线。

当每个人都拥有一个可以被 AI 使用、也可以与他人协作的知识大脑，AI-native 组织才真正有了基础。

## 事实边界

- 当前知识库能力包括本地 Markdown、目录、搜索、Wiki 链接、Git 版本历史、备份恢复、聊天草稿沉淀和 `most://` CID 附件引用。
- 当前 MCP 只开放节点和文件能力，尚未开放知识库读取、整理或写回。
- 个人知识库间的选择性上下文分享、AI 知识整理和组织知识网络属于未来方向。
- MostBox 文件传播仍遵守 CID 唯一内容身份、完整副本、下载校验、下载后做种和在线种子可用性边界。
