# MostBox DChat 验收指南

本文件验证当前版本的主线：**P2P 频道聊天为本、`most://` 文件传输为辅**。MostBox 不提供云端消息或文件存储；可用性来自在线节点。

长期最高目标是成为能脱离创始人长期存在的公共协议。本文件分别验证功能可靠性与[公共协议独立性](#公共协议独立性验收)，两者不能相互替代。

## 当前入口

| 入口      | 用途                                         |
| --------- | -------------------------------------------- |
| `/chat/`  | 创建或加入频道、发送消息、查看历史、发送附件 |
| `/file/`  | 发布文件、接收 `most://` 链接、查看做种列表  |
| `/admin/` | 节点、做种、日志和远程连接状态               |
| `/web3/`  | 独立的本地账户、密钥和钱包工具               |

桌面端默认打开根路径 `/` 的功能入口页，可从中进入 `/chat/`；营销页 `/hi/` 说明 DChat 定位。旧 `/note/` 路由和 `/api/note-vault/*` 接口不存在。

## 最小聊天验收

1. 分别运行 `npm start` 和 `npm run server`，再打开 `http://localhost:2020/`。
2. 确认根路径进入聊天，三种语言都显示“去中心化聊天与文件传输”定位。
3. 创建频道，复制 `/chat/#<channelId>` 邀请链接；另一浏览器或另一节点加入。
4. 双向发送文本，确认消息顺序、发送者和时间正确。
5. 刷新页面、断开再连接，确认频道历史仍可读取。
6. 发送一条聊天附件，确认消息中出现 `most://` 链接，文件可打开下载确认流程。
7. 当前验收先覆盖全功能版；两个商店版后续按实际构建功能矩阵另验，不能以历史墨盒 profile 的 UI 开关认定隔离完成。

## 文件与接力验收

1. 节点 A 发布文件并复制 `most://<cid>?filename=...`。
2. 节点 B 粘贴链接，确认下载前有确认步骤，完成后 CID 校验通过并加入 holding。
3. 确认 B 的做种状态为 active，重启 B 后重新 join 对应 CID topic。
4. 退出 A，保持 B 在线，让节点 C 使用同一链接下载并通过 CID 校验。
5. 文件名只用于展示，已有判断、Hyperdrive 路径和完整性校验都以 CID 为准。

## 数据删除与备份迁移

- Web 首次启动删除旧 `mostbox` IndexedDB、`mostbox.chatNoteDraft.*` 和 Expo Web 知识库键。
- Electron 首次启动删除 `Documents/MostBox/Notes`，路径固定在 Documents/MostBox 内，不跟随越界路径。
- Android/iOS 首次启动删除应用文档目录中的 `mostbox-knowledge` 及导入临时目录。
- 清理失败只记录日志并在下次启动重试，不阻塞聊天或文件功能；其他身份、频道、文件和做种数据必须保留。
- 新备份不含 `notes`、`noteVault`；导入旧备份时丢弃这两个字段，其他账户数据仍可恢复。
- 账号错误、密码错误、ownerAddress 不匹配仍必须拒绝导入。

## P0 可靠性回归

- 生产构建：`npm run build` 和 `npm run check:static-output` 通过后，打开 daemon 的 `/chat/`、`/file/`、`/docs/api/`；刷新后页面仍可交互，Scalar API 参考完成加载，控制台没有初始化错误。Electron 使用同一生产输出做窗口验收。
- CID 边界：根项目和移动端测试均覆盖 UnixFS 文件大小的 2GiB、4GiB、10GiB 整数编码；既有空文件、小文件和跨块黄金 CID 必须保持一致。
- 移动本地可用性：保留 holding 和 Hyperdrive entry，清除实际 blob；重启后状态为 error、`localAvailable: false`，不恢复种子 topic，不返回 `alreadyExists / completed`，也不能导出。重新发布同一内容后恢复完整副本和默认做种。零字节文件仍算有效完整内容。
- 缓存路径：导出时校验路径中的内容是否属于该 CID；路径内容被替换后，从 `/<cid>` 重建正确副本，不覆盖用户原路径。

UnixFS 的 `protons-runtime` 7.x / 8.x 整数编码补丁由根项目和移动子包的 `postinstall` 自动应用。使用 `--ignore-scripts` 安装后，必须分别运行 `npm run postinstall` 和 `npm --prefix app run postinstall`，再计算 CID 或生成 Bare bundle。升级该依赖时必须重新验收补丁和黄金样本。

大文件专用回归需安装两个包的依赖，并预留至少 20GiB 临时磁盘空间：

```bash
npm ci
npm ci --prefix app
npm run test:large-files
```

该测试生成 2112MiB 文件，验证文件路径与不同读取块大小的 CID、桌面下载与发布者退出后的种子接力，以及移动生产核心在 Node 宿主机上的发布和重启。测试结束清理自身临时目录；它不属于常规 `npm test`，也不替代 Android/iOS 真机和公共网络验收。

## 移动文件体验回归

- Android 系统保存使用 `app/modules/most-file-export` 本地原生模块，需要重新构建 APK；Expo Go 或仅更新 JS 不包含该模块。
- 在 192MiB heap growth limit 的模拟器上，把已校验的 32MiB holding 保存到系统目录；读取输出并对比完整字节数与 SHA-256。再在 ARM64 真机上验证 256MiB 和 2GiB 以上文件，并记录内存峰值。
- 同名保存生成新文件，原文件保持可读，成功提示显示实际输出名称。取消选择目录不创建输出，也不提示保存成功。
- 复制或输出复读校验失败不能提示成功；新建的不完整输出应删除，无法删除时明确提示用户检查残留文件。另验空间不足、目录权限撤销和异常文档提供者。
- 聊天中的结构化附件和纯 `most://` 消息均可点击。未持有完整 CID 时先进入现有下载确认页；有大小 metadata 时显示大小；运行中显示进度，失败后提供重试，只有本机确认可读的同一 CID 才提供打开入口。
- 附件完成后保持原有 CID 校验、写入 `/<cid>` 和默认做种；再次执行发布者退出后的接力验收。

原生流复制的 JVM 回归可在生成 Android 项目后运行：

```powershell
cd app/android
./gradlew.bat :most-file-export:testReleaseUnitTest
```

该测试覆盖固定缓冲区复制、空文件、超过 2GiB 的计数、源长度变化、同长度损坏、截断输出和写入异常时关闭流；它不替代 SAF 文档提供者与实际界面验收。已有验证和未覆盖项见[验证状态](validation-status.md)。

## MVP 深度验收

本节是 AGENTS.md「当前 MVP 口径」中失败模型、不变量 F1–F5 / C1–C5、量化门槛和证据要求的执行方式。上面的「最小聊天验收」「文件与接力验收」只证明正常路径走通，不能替代本节。

### 执行原则

1. 门槛以 AGENTS.md「量化门槛」为准；如需调整，先改门槛并提交，再开始测试；不达标即失败，不事后改口径。
2. 只用原始数据下结论：每次运行输出 JSONL 事件（发送、确认、观察、announce、lookup、连接建立及路径、传输字节、CID 结果、错误），统计由脚本从事件计算。
3. 可重放：记录随机种子、提交号、包 SHA-256、设备/OS、NAT 类型；他人在干净环境用同一命令应得到同分布的结果。

### 聊天

- 每个节点记录发送、确认、观察三类事件；离线检查器在合并后的历史上验证 C1 已确认不丢、C2 不重复、C3 同一发送者有序、C4 分区恢复后在线成员收敛到同一集合。
- 故障注入：随机断连、网络分区与恢复、进程重启，≥100 轮，C1–C4 零违例；记录分区恢复到收敛的时间，P95 ≤30s。
- C5：所有其他成员离线时，记录重连后本机实际可读的历史范围，写入本文件作为产品边界。
- 现有覆盖：三节点文本双向中继、重启后重开频道 core 与继续写入。`npm run stats:chat-chaos -- --rounds 300 --rng <种子> --out <log>`：4 个桌面引擎经内存复制（`replicateWith`）组成全连接，每轮随机分区、重启、同 `clientMessageId` 重发与重复文本，恢复后记录每个节点的历史；`--summarize <log>` 从原始日志重算 C1–C4 与收敛时间，并记录 C5 边界。`channelPartialCore.test.js` 与移动核心测试覆盖“远端 core 缺块且作者离线时启动、读取、发送不挂起，作者回来后补齐”。
- 未覆盖：真实网络（Hyperswarm/DHT）下的分区注入、`kill -9`（只测正常停止）、移动核心参与的混沌轮次。

### 测试有效性与输入健壮性

- 变异测试（如 Stryker）针对 `server/src/core/cid.js`、下载校验与 holding 恢复路径；故意改坏校验时测试必须变红。三条路径合计得分 ≥85%，CID 比较判断的变异体 100% 被杀死。**待建**。
- 属性测试/模糊测试（如 `fast-check`）覆盖 `most://` 解析、频道帧编解码与历史合并。**待建**。

### 隐私边界实测

用第三个节点只凭 CID 在 DHT 上 lookup 对应 topic，记录能枚举到的做种者地址，确认与隐私政策披露一致。`node scripts/dht-enumerate.js '<most://链接>'` 先 lookup topic 列出公告记录，再像普通下载者一样逐个连接，记录连接的对端地址（经中继时为中继地址）。结果见[验证状态](validation-status.md)。

## 群模型与消息状态验收

对应[群聊模型](chat-model.md)，状态为**待设计用例并执行**；本次文档更新不代表已验证下列行为，也不修改 C1–C5 的既有定义和门槛。

- 群内权限：创建者、后加入者与志愿常在线成员均为普通用户；加入不需管理员批准，运行节点不增加群权限。现有节点管理台的授权仍独立验收。
- 唯一加入值：用户创建、分享、输入同一个产品 `channelId`，无需另一份邀请码；随机群与可猜公开群按现行规则分别加入，分享值和内部派生 ID 的对应正确，不把私密群的加入值写进公开日志。
- 历史平权：在指定目标版本内，新成员可取得仍由可达节点持有的加入前签名消息；缺块或持有者离线时明确显示边界。不将历史版本兼容或旧快照迁移列为本项前提。
- 群成员自建节点（2026-11-22 补充）：由非创始人成员部署常在线服务器节点并加入群；发送者的消息同步至该节点后退出，另一成员随后上线仍可补齐。覆盖服务器重启后的历史恢复及所有持有副本的节点不可达时的等待提示，不承诺随时送达或永久保存。维护者与其他成员权限相同，不要求每位成员自建；常在线不触发全部附件下载，纯中继不作为消息保存证据。验收仍待执行，不以本次文档记录代替结果。
- 数据自管与更换节点（2026-11-22 补充，待设计并执行）：在同一目标版本，用合成身份连接远程节点 A，加入群、收发带标识的文字并按需下载文件；按预先公开的方案将身份恢复材料、群入口、已同步消息与已下载文件保存至用户控制的设备或备份。永久阻断 A，禁止读取 A 的数据目录或要求运营者配合；分别验证用户设备保留数据时的切换，以及从用户备份在干净客户端恢复后连接 B。核对身份公钥、群加入值、已有消息内容与签名、文件字节与 CID，确认可读取原有内容并与在线成员继续签名收发；无重复消息或身份替换，不以 B 的缓存掩盖本地恢复失败。未同步消息与未下载附件仅在仍有可达副本时补齐；无副本时如实告知。记录版本、步骤和原始证据，不以现有账号备份或单次重新登录代替验收，不新增历史版本兼容要求。
- 附件按需：加入群、同步历史和滚动列表均不自动获取完整附件；用户点击时下载，本地已有同一可读取 CID 时打开现有副本。覆盖图片、语音、普通文件、离线与失败重试，下载须 CID 校验通过并默认继续做种；再次验收发布者退出后的接力。
- 换群：泄露后用新随机 `channelId` 建立空群；仅知道旧值不能加入新群。旧群和已持有副本仍能存在，不显示“全网删除”或“旧凭据已撤销”等无证据承诺。
- 消息状态（低优先级，暂不开发，不作为当前 MVP 验收门槛）：未来显示收到用户名单，不做已读；启用前先独立设计回执机制和协议格式再验收。届时用例须覆盖后台收到、未打开聊天、未下载附件、未收到回执、同版本未启用回执能力和断线重启。不能从在线状态或中转节点持有推断某位用户收到，不能从未收到回执推断未收到消息，也不能从收到推断副本永久可用。不为历史版本补兼容用例或协议分支，不把产品“收到”状态直接替换为既有 C1–C5 中“已确认”的定义。
- 失败引导：区分连接、同步、历史缺块和附件缺少在线种子，依据可观察事实提供适用的等待或恢复操作；不得把超时直接解释为内容永久丢失。

## 公共协议独立性验收

本节落实[长期方案](decentralization-plan.md)的成功标准，2026-11-21 确定。**状态：待设计工具、待执行，尚无整体验收结论。** 不将本次文档更新、桌面与移动互通或维护团队自行写的替代实现记为第三方接手完成。

### 范围与准备

- 先公开独立实现的必选范围、一致性用例、服务依赖清单与演练步骤，再执行并记录结果；不事后缩小范围以宣布通过。
- 首个最小实现覆盖现行 v2 的频道授权、客户端签名文本与必要的证书验证、历史同步，以及 `most://` 解析、`most-cid-drive/3`、下载后 CID 校验和持续做种。不要求 UI、语音、Web3、MCP 或商店包；省略能力须如实声明，签名等必选行为不得省略。
- 独立实现由未参与参考核心实现的第三方依据公开规范和向量完成，不复制、导入或调用本仓库生产协议核心。可复用公开上游库和共享测试向量，记录具体组件与版本；不要求不同语言或重写 Holepunch 栈。
- 实现与互通验收绑定同一目标协议版本；协议发生不兼容升级后更新规范、向量与候选包再重跑，不把历史版本兼容或迁移列为默认门槛。
- 演练在隔离测试环境进行，使用合成身份、频道和文件；阻断服务不影响实际用户，不共享真实私钥或官方账号。

### P1：知识交接与独立互通

1. 第三方记录所用规范与向量版本、上游依赖、实现提交和制品哈希；将每处必须询问作者的歧义登记为问题，补充公开文档后再重放。
2. 参考节点 A 与独立节点 B 加入同一测试频道，双向发送签名文本，断连重连并重启后核对消息集合、去重和同发送者顺序。非法签名与无频道授权的请求必须拒绝。
3. A 发布文件，B 按链接下载并重算 CID 后做种；关闭 A，空数据目录的 C 仅凭频道凭证与文件链接加入并从 B 下载，独立核对字节与 CID。
4. 交换参考实现与独立实现的发布者、下载者角色，重放文件接力；错误内容不得保存或做种。保留未知可选能力的处理与必选签名拒收用例。

此项证明所声明最小范围的独立互通；F1–F5、C1–C5 的完整故障模型与量化统计仍按「MVP 深度验收」执行，不因单次互通通过而豁免。

### P2：创始人退出与新节点加入

1. 清点并阻断测试环境中的官方域名、服务器、引导、中继与更新服务，保存阻断规则、实际请求或连接日志。列明仍依赖的第三方服务。
2. 接手者从事先公开保存的源码或安装包部署节点与替代引导、必要的中继，使用自己的配置和密钥。替代引导须独立运行；继续使用默认上游引导节点不算完成引导接替。
3. 分别验证已有群体继续通信、重启后恢复和空数据目录的新节点发现加入；新节点不得沿用隐藏的节点缓存、作者提供的未公开地址或临时口头步骤。明确它从公开分发材料或用户提供的第三方配置中如何获得引导信息。
4. 完成签名文本双向同步与发布者退出后的文件接力；对替代引导、中继条件重跑既定 F5 门槛并记录实际连接路径，不能仅凭拓扑推断路径。

### P3：维护与分发交接

- 非创始人依照公开流程，在干净环境获取依赖、构建并发布使用自身签名的发行版，记录源码与依赖版本、构建环境、制品哈希和重放命令；未达到可复现构建时如实说明差异。
- 记录签名、仓库或分发地址变化后的用户安装与迁移边界，不假设第三方能沿用官方更新通道或商店账号。
- 用一次真实文档修正、兼容性修复或扩展提案验证交接，公开问题、决策理由与验证证据；由接手者完成维护和分发，不依赖创始人单独批准或代操作。

### P4：群体自主运行

由有实际通信和文件需求的群体自行部署、邀请成员、恢复故障并维护节点。预先记录观察周期和场景，报告维护者、节点在线情况、失败与作者介入次数；作者介入解决的步骤须补回文档，再由接手者独立重放。无人在线时的不可用、成员节点可读历史与后台限制须告知参与者。

### 证据与结论

P1–P4 分项报告通过、失败或未执行，声明实现范围及剩余依赖；结论写入[验证状态](validation-status.md)，原始日志和重放说明归档到 `docs/evidence/`。记录提交、规范与向量版本、包 SHA-256、设备/OS、网络与连接路径、随机种子（适用时）、阻断条件和作者介入情况。对外公开前按隐私要求脱敏。
