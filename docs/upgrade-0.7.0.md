# MostBox 0.7.0 升级说明（自建节点）

本文面向自建 MostBox 节点、并通过 `https://most.box/chat/join#<token>` 邀请链接接入聊天的客户。适用于从 0.5.x 或 0.6.x 升级到 0.7.0。

## 概要

0.7.0 升级了聊天协议（协议 v2）：每条消息、成员资料、在线状态和语音信令都由用户设备签名，节点无法再冒充用户发言。

**这是一次不兼容升级。** 0.7.0 与 0.5.x / 0.6.x 的节点和网页之间，聊天和文件都不互通。所以需要约定一个维护窗口：您升级自建节点的同时，我们切换 most.box 网页。

## 升级后用户会看到的变化

| 项目     | 变化                                                                                                                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登录     | 用户照常打开邀请链接即可。首次进入时自动迁移到新的聊天身份，无需额外操作。                                                                                                                         |
| 聊天身份 | 聊天身份与钱包分离，**聊天地址会改变**；钱包地址不变。如果您的系统保存了用户的聊天地址，请按新地址更新。                                                                                           |
| 历史消息 | 升级前的文字消息保留为只读，带「未签名」标记（作者名是旧版自填的，存放在本节点，仅本节点可读）。只有升级时已在频道里的成员能看到；**升级后新加入的成员看不到旧消息**。                             |
| 旧附件   | 升级前聊天里的文件、图片附件，在历史中显示为一行 `most://` 链接文本，不能在聊天里直接点开。文件本身仍在节点上，可在文件库中找到并打开。                                                            |
| 频道     | 邀请链接里的频道 ID（如 `005c8db8d4914eb2` 这类自定义 ID）会成为「公开频道」，频道详情中注明：知道 ID 的人都可以加入并阅读。这与原来的实际情况相同，只是现在明确标出。新建私密频道会使用随机凭证。 |
| 文件     | 文件列表、`most://` 分享链接和文件内容都保留，按 CID 下载和校验的方式不变。                                                                                                                        |
| 首次进入 | 进入时身份计算约需 0.5–1 秒，手机浏览器上页面会短暂没有响应，属于正常现象。                                                                                                                        |

## ST 后端是否需要修改

- **只生成邀请链接**：链接格式和生成代码不变（见 [ST 邀请集成](st-chat-join-integration.md)），不需要修改。
- **自行调用 WebSocket / HTTP 聊天接口**（不经过 most.box 网页）：需要按新版[原生聊天协议](native-chat-protocol.md)改为提交签名消息，旧格式的请求会被拒绝。如有这种情况请提前告诉我们。

## 升级前准备

1. 与我们约定维护时间。窗口内您升级节点，我们切换 most.box 网页。
2. 确认服务器时间已开启 NTP 同步。签名有效期按节点本机时间判断，时钟不准会导致登录失败。
3. 确认数据目录位置和磁盘空间：
   - 数据目录默认是 `~/most-data`，配置文件在 `~/.most-box/config.json`；配置了 `dataPath` 的以实际值为准。
   - 备份需要与数据目录同等大小的空间，并且**必须和数据目录在同一个文件系统上**（原因见「回滚方法」）。
4. 建议先在测试节点上完整走一遍下面的步骤和验收。

## 升级步骤

以下以 Linux、数据目录 `/data/most-data` 为例，请替换成您的实际路径。

1. **记录当前状态**：记下当前节点版本，可在 `/api/node/status` 查看 `version`（远程访问需带 `x-mostbox-invite` 请求头）。
2. **停止节点**：暂停业务写入后，正常停止节点进程（例如 `pm2 stop <name>` 或 `systemctl stop <service>`），确认进程已退出。不要在节点运行时复制数据目录。
3. **备份数据目录和配置**（同一文件系统上）：

   ```bash
   cp -a /data/most-data /data/most-data.bak-before-0.7.0
   cp -a ~/.most-box ~/.most-box.bak-before-0.7.0
   ```

4. **安装 0.7.0**：按您原来的方式（npm / Docker 镜像 `ghcr.io/most-people/most-box:0.7.0` / 安装包）换成 0.7.0。**继续使用原来的数据目录**（不要让新版直接打开备份副本），配置保持不变。
5. **启动节点**：首次启动会自动迁移文件和频道记录，日志中会出现 `Migrated <cid> to its own seed drive`。期间不要强制结束进程。
6. **检查版本**：`/api/node/status` 中的 `version` 应为 `0.7.0`，`holdings` 里没有 `error` 状态。
7. **通知我们**：我们切换 most.box 网页后，由您用邀请链接做下面的验收。

## 升级后验收

请用升级前就存在的客服账号和用户账号，通过邀请链接进入，逐项确认：

- [ ] 能正常进入频道
- [ ] 能看到升级前的文字消息，带「未签名」标记
- [ ] 频道详情中的成员人数正确
- [ ] 文件库中能看到升级前的文件，任选一个能打开
- [ ] 客服与用户能互相收发新消息（对方重新进入频道后可见）
- [ ] 节点上没有处于错误状态的文件记录

全部通过后再恢复正常业务。

## 回滚方法

数据目录里的 `CORESTORE` 文件是存储设备标记，里面记录了这个文件自身的 inode。**直接把备份目录复制回去是无法启动的**（会报「存储文件损坏」）。回滚时要把原目录里那个 `CORESTORE` 文件移动（不能复制）到恢复后的目录中。

如果验收不通过：

1. 停止新写入，停止 0.7.0 节点，并通知我们回退 most.box 网页。
2. 保留升级后的目录，恢复备份，并移回原 `CORESTORE` 标记文件：

   ```bash
   mv /data/most-data /data/most-data.after-0.7.0
   cp -a /data/most-data.bak-before-0.7.0 /data/most-data
   mv /data/most-data.after-0.7.0/CORESTORE /data/most-data/CORESTORE
   rm -rf ~/.most-box && cp -a ~/.most-box.bak-before-0.7.0 ~/.most-box
   ```

3. 换回旧版程序并启动，用邀请链接确认旧消息和文件都在。

注意：

- **不要用旧版程序直接打开已经迁移过的数据目录**，迁移是单向的。
- `mv` 只有在同一文件系统内才会保留 inode；跨磁盘的备份无法按上面的方法恢复。
- 切换后新产生的消息会留在 `most-data.after-0.7.0` 中，回滚后旧版不可见，请不要删除该目录。

## 其他说明

- 节点默认不配置中继。如需中继，请在节点配置中自行设置 `relayPublicKey`。
- 知道文件 CID 的人可以通过 DHT 查到正在做种的节点 IP，这一点与之前相同，详见隐私说明。
- 升级过程中有任何异常，请保留节点日志并与我们联系。
