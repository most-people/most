# MostBox 协议规范

状态：**现行实现为 v2（0.8.0 起）**。项目仍处早期，未来较长阶段不承担历史版本兼容，稳定兼容时间另行确认。本目录描述当前代码的线上行为，不因策略更新自动改变既有字节格式。

阅读规则：本级目录的文件（原 v1 描述）给出基础结构；[v2/](v2/README.md) 中的各文件说明 0.8.0 改了什么。两者冲突时**以 v2 为准**；每个 v1 文件开头列出了被 v2 取代的章节。后续迭代按 [v2/envelope.md](v2/envelope.md) §7 明确目标版本，不默认提供历史兼容层。

目标读者：不看本仓库代码、要实现第二个兼容客户端的人。

产品中的 `channelId` 是用户标识并加入群的唯一值，对应现有输入 `handle`；本目录 v2 线上字段 `channelId` 是内部公开派生值。这里的“频道凭证”只是加入值的技术名称，不是第二份用户凭证。两者映射、普通用户平权模型与未实现需求见[群聊模型](../chat-model.md)；映射描述当前实现，不要求永久保留历史命名。

最高目标是让第三方能够接手协议的实现、运行和维护。规范与向量已有初版；独立第三方能否仅凭这些材料实现互通，仍待[公共协议独立性验收](../acceptance.md#公共协议独立性验收)，不能从双端测试通过推定。

## 独立实现入口

1. 先读本级基础章节，再按每篇开头列出的覆盖关系读取 v2；v2 是现行语义，禁止按旧 topic、共享密钥或未签名帧实现新节点。
2. 首个最小实现覆盖身份与设备证书、频道授权和签名文本同步，以及文件发现、下载校验与做种；具体范围按[验收指南](../acceptance.md#公共协议独立性验收)预先确认。UI、语音、MCP 和官方账号不作为该最小范围的前提。
3. 线上格式从[标识符](identifiers.md)、[发现](discovery.md)、[连接](connection.md)、[文件传输](file-transfer.md)、[聊天](chat.md)及其 v2 覆盖章节读取，使用[共享向量](vectors/README.md)核对字节。独立实现声明目标协议版本；协议演进遵守 [envelope §7](v2/envelope.md#7-协议演进规则)。
4. 可复用公开的 HyperDHT、Hyperswarm、Protomux、Hypercore、Hyperdrive 等上游库，列明版本与来源；仅调用本仓库核心、HTTP API 或更换界面不能证明独立的 P2P 协议实现。
5. 文档缺失的字段、错误处理或上游要求登记为规范问题，补充可复现样例与向量。代码位置用于核对参考实现，不代替规范说明；独立实现中发现的歧义须补回公开材料。

协议核心保持互通、授权、完整性和演进所需的最小范围；客户端界面、平台适配与运营服务可以各自选择。第三方实现和自行分发遵守仓库许可，无需创始人批准；维护提案与兼容性证据见[贡献指南](../../CONTRIBUTING.md#独立实现与协议维护)。

## 约定

- 每条规范陈述后用「桌面：」「移动：」标出实现位置（路径:行号，写作时的行号）。两端行为不同时单列「两端差异」，不替任何一端取舍。
- 「必须 / 不得」表示不遵守就无法与现有客户端互通或会破坏不变量；「当前」表示现状描述，不是要求。
- 桌面指 `server/src/`（Node daemon，Electron 与 Web 管理台共用）；移动指 `app/backend/`（Bare Worklet）。
- 字节示例用小写十六进制；`‖` 表示字节拼接。
