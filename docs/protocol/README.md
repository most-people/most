# MostBox 协议规范

**[从现行 v2 规范开始阅读](v2/README.md)。** 本目录只保留一套现行正文：按阅读顺序说明原语、连接、发现、频道授权、用户签名、聊天与文件传输。无需对照旧协议和覆盖说明。

目标读者是要独立实现兼容节点的人。参考实现自 0.8.0 起使用 v2；项目仍处早期，不承诺历史版本兼容。后续变更遵守 [版本规则](v2/envelope.md#7-协议演进规则)，本次整理不改变线上字节。

## 独立实现入口

1. 按 [v2 目录](v2/README.md) 连续阅读，按 [向量分类](vectors/README.md) 核对当前字节，不能把旧回归夹具当作新网络格式。
2. 最小实现覆盖设备身份、频道授权、签名文本同步，以及文件发现、下载校验与做种。UI、语音、MCP 和官方账号不是最小范围的前提；具体声明范围按 [公共协议独立性验收](../acceptance.md#公共协议独立性验收)预先确定。
3. 可复用公开上游库并列明来源与版本；仅封装本仓库生产核心、调用 HTTP 或换界面，不能算独立 P2P 实现。
4. 发现规范缺失时，公开可复现样例与向量并补回正文。代码位置用于核对，不能代替字节规范。版本互通、官方服务退出和维护交接都需要独立证据。

第三方实现、运营与自行分发无需创始人批准，仍遵守仓库许可和权限边界；见 [贡献指南](../../CONTRIBUTING.md#独立实现与协议维护)。规范整理和双端回归不代表第三方独立实现已经通过验收。

## 约定

“必须 / 不得”表示互通或不变量要求；“参考实现 / 当前”表示已存在行为。桌面指 `server/src/`，移动核心指 `app/backend/`；客户端接口与线上 P2P 字节分开描述。实现差异、失败记录和迁移适用范围明确标注，不默认为已解决或永久兼容。

产品只使用一个群加入值；输入 handle 与线上公开 channelId 的区别见 [标识符](v2/identifiers.md#3-频道标识)。[群聊模型](../chat-model.md)记录产品决定，[验证状态](../validation-status.md)记录证据和缺口。
